**编辑指南**说明 YJlab 维基的编辑方式、语法约定与页面规范。本站采用与维基百科相同的写作习惯：**没有主编，任何人发现问题都可以直接改**。

## 谁可以编辑

| 身份 | 权限 | 获取方式 |
| --- | --- | --- |
| 浏览者 | 阅读、搜索 | 无需任何操作 |
| 编辑者 | 新建与修改任意页面 | 由管理员把仓库写权限授予其账号 |
| 管理员 | 编辑 + 改站点配置 + 加人 | 现有的管理员在仓库设置里添加 |

::: ambox 权限即账号
本站是静态站点，没有独立的注册系统。"管理员账号"就是**代码仓库上的账号**。想加人，去仓库的 Settings → Collaborators 里添加即可。
:::

## 三种编辑方式

### 方式一：网页上直接改（最常用）

1. 打开任意页面
2. 点右上角的「**编辑**」标签
3. 在网页编辑器里直接改 Markdown 文本，可以用「Preview」标签预览
4. 在页面底部写一句改动说明，点 **Commit changes**
5. 约一分钟后站点自动重建，改动生效

这是最接近维基百科体验的方式，**不需要装任何软件**。

### 方式二：图形化后台（不熟悉 Markdown 时用）

仓库里带有 `.pages.yml` 配置，用 [Pages CMS](https://pagescms.org/) 登录后可以获得表单式的编辑界面：左边选页面，右边填写标题、分类和正文，保存即提交。

### 方式三：本地编辑（大批量修改时用）

```bash
npm install
npm run dev      # 打开 http://localhost:5173 实时预览
# 改完后
git add -A && git commit -m "更新第三世代人员" && git push
```

## 一次编辑的完整流程

1. **先搜索**，确认页面是否已经存在，避免建重复页面
2. 修改正文，长段落请拆成小标题
3. 在文件开头的 frontmatter 里补上 `categories`，页面底部会自动出现分类栏
4. 在相关条目之间加互链，**维基的价值在于链接而不在于文字量**
5. 写清楚改动说明

## Markdown 速查

| 想要的效果 | 写法 |
| --- | --- |
| 二级标题 | `## 标题` |
| 加粗 / 斜体 | `**加粗**` / `*斜体*` |
| 站内链接 | `[ROS组](/groups/ros)` |
| 外部链接 | `[维基百科](https://zh.wikipedia.org/)` |
| 无序 / 有序列表 | `- 项目` / `1. 项目` |
| 表格 | 见下方示例 |
| 图片 | `![说明](/images/图.png)` |
| 代码 | 行内 `` `code` ``，整段用三个反引号包围 |
| 待办清单 | `- [ ] 未完成` / `- [x] 已完成` |
| 分隔线 | `---` |

::: ambox 中文标点可以放心写在加粗里面
`**注意：**请勿修改`、`**第一世代（猴王初问世）**是…` 这种写法在本站是正常的，会正确加粗。这是本站专门修过的行为——别的 Markdown 编辑器里可能会失效，不用管它们。
:::

表格写法：

```md
| 姓名 | 角色 | 在组时间 |
| --- | --- | --- |
| 张三 | 负责人 | 2023– |
```

## 本站特有语法

除了标准 Markdown，本站额外提供三种维基风格的提示框。

**消歧义提示**（斜体、缩进，用于页面顶部指向其他条目）：

```md
::: hatnote
本条目介绍的是常设组别。关于历史沿革，请见[世代编年史](/chronicle/)。
:::
```

**条目通告框**（左侧橙色竖条，用于提醒读者）：

```md
::: ambox 本条目需要补充
这一节还缺少 2023 年之后的信息。
:::
```

**信息框**（浮动在右上角，用于条目摘要）：

```md
::: infobox ROS组
| 项目 | 内容 |
| --- | --- |
| 成立时间 | 2021 年 |
| 现任负责人 | 待补充 |
:::
```

## 写作规范

::: infobox 五条硬规矩
| 规矩 | 说明 |
| --- | --- |
| 客观优先 | 写发生过什么，而不是评价谁好谁坏 |
| 署名到人 | 事项尽量注明负责人与时间，方便追问 |
| 不写隐私 | 手机号、身份证号、家庭住址、未公开的评审意见一律不写 |
| 不复述 | 别把别人的文档整段抄过来，给出链接即可 |
| 留改动说明 | 一句话说清这次改了什么 |
:::

## 页面命名与分类

- 文件名用**英文或拼音**，短横线分隔，例如 `gen-1.md`、`algorithm.md`
- 页面标题写在 frontmatter 的 `title` 字段里，用中文
- `categories` 只能填侧栏里的三大分类：`世代编年史`、`组别`、`工具介绍`
- 每新增一个页面，记得在 `docs/.vitepress/config.mts` 的 `SIDEBAR` 里加上链接，否则它不会出现在侧栏

## 图片与附件

把图片放进 `docs/public/images/` 目录，然后这样引用：

```md
![组会照片](/images/group-meeting-2024.jpg)
```

::: ambox 不要上传大文件
超过 5 MB 的图片请先压缩；数据集、PPT、原始实验记录不要放进仓库，改放到网盘后在页面里贴链接。
:::

## 常见问题

**改错了怎么办？**
不用担心。每次提交都有完整记录，管理员可以在仓库的提交历史里一键回退，也可以点页面的「查看历史」标签找到旧版本。

**页面没出现在侧栏？**
侧栏是手工维护的，需要在 `config.mts` 的 `SIDEBAR` 数组里添加对应的 `{ text, link }`。

**能不能删页面？**
可以，在仓库里删除对应的 `.md` 文件，同时把侧栏里的链接一并删掉，否则会留下一个红链。
